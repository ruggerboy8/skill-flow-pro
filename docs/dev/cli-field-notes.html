CLI Field Notes

Working habits for Warp + Claude Code, written for how you actually think about product work — not a generic terminal tutorial.

Starting and resuming

  • Ritual: cd into the repo, then claude. That's it.
  • Picking up where you left off? Don't start fresh — use claude --continue, or claude --resume to choose from recent sessions. A new conversation forgets everything about what you were mid-way through.
  • One feature, one session. Open a new Warp tab for unrelated work instead of steering one conversation through two different things.

The habits that keep you safe

  • Plan mode before anything non-trivial. shift+tab cycles into it — Claude shows you the plan before touching a file. This is your approval gate, built into the tool itself.
  • Interrupting is always safe. Esc stops Claude mid-action. Don't let a "wait, that's not it" moment run to completion out of politeness.
  • There's a safety net before git. Claude Code tracks the edits it makes within a session. If something looks wrong, just say it:
"Undo that last change, put the file back."
  • Nothing should reach main without a PR you see first, once the workflow kit's guard hook is in. Unsure? Just ask.

How to talk to Claude

Your instincts here are already right — describing behavior is the actual skill.

  • Say the outcome, not the implementation. "Coaches should be able to flag a favorite move" beats guessing at a component name.
  • Name the "who." This week's lead-account bug only showed up for one persona. Say which account/role/screen matters when you ask for or test something.
  • Ask for plain English, as a standing habit — not an admission of anything:
"Explain what you just did like I don't read code."
  • Say when a plan feels off before you approve it. One sentence now beats a redo later.

The short command list

Deliberately small — these are the ones that pay for themselves.

/modelsee or switch which Claude model you're talking to /clearwipe the conversation, start clean (not for resuming — for truly new work) /helpeverything else, so you never memorize the full set /permissionssee and adjust what Claude can do without asking first /doctorself-diagnose the Claude Code tool itself /initregenerate CLAUDE.md if the project's own docs feel stale

Cutting "may I do this?" fatigue

Claude asks before anything it's unsure is safe — correct, but tiring for the same harmless repeats. Every few weeks, run:

/fewer-permission-prompts — looks at recent sessions, finds the read-only actions you keep approving, adds them to an allowlist.

Long tasks and verification

  • Don't watch the spinner. Ask Claude to run long things in the background and let you know when done.
  • The verification loop hasn't changed. Visual or data-shaped work still gets checked on the Lovable branch preview, as the right persona, against the acceptance script. Everything else: ask for the QA report in plain language.
  • Ask what couldn't be verified, specifically. "Not verifiable live" is a signal to act on, not a red flag.

When the terminal looks broken

Don't decode an error yourself. Paste the whole thing back:

"What does this mean, and what should I do?"

Usually the fastest path either way, not just a fallback for when you're stuck.
