Restart to Shipped

Four tools, one job each. This is exactly what happens, in order, from turning your computer on to a new feature going live.

The four tools

Warp

Where you talk to Claude and it writes the code.

GitHub

Where you click one green button: Merge.

Lovable

Where you look at the app, then click Publish.

Motion

A board you can glance at. Nothing to do here.

The path a feature takes

The walkthrough

1

Warp: describe it, let Claude build

Warp
  1. Open Warp. Type cd ~/skill-flow-pro, then claude.
  2. Tell Claude what you want, in plain English.
  3. Claude proposes a plan. You read it and say “approved” or ask for changes. you decide
  4. Claude builds it, tests it, and pushes a branch with a pull request. This part you can walk away from.
2

Lovable: look at it

Lovable
  1. Claude tells you the branch name.
  2. In Lovable, open the branch picker and switch to that branch. The preview rebuilds.
  3. Click through it like a customer would. you decide
  4. Not right? Tell Claude what's off — back to step 1. Looks good? Switch the branch picker back to main.
Don't skip this switch-back. Publish always ships whichever branch Lovable is currently pointed at.
3

GitHub: make it official

GitHub
  1. Open the PR link Claude gave you.
  2. Click the green Merge pull request button. you decide
4

Lovable: ship it

Lovable
  1. Lovable notices main changed and re-syncs on its own.
  2. Click Publish. you decide
  3. It's live.

Where does Motion fit in?

It doesn't sit in this path. It's a board Claude keeps updated with what's queued, being built, or waiting on review. Open it whenever you're curious "where are we" — you never have to act on anything there.
